# CS 1501 Portfolio Context

## Building Software with AI Systems

This document is context for an AI coding agent working on Chloe
LaForge's portfolio. It describes the CS 1501 case-study page as it
currently appears in the supplied screenshots, including its visual
language, hierarchy, content, interactions, and the ideas the page is
trying to communicate.

The goal is not to redesign the page from scratch. Treat the screenshots
and this document as the existing implementation. Unless a future prompt

styling, spacing logic, typography, navigation, and content.

------------------------------------------------------------------------

## 1. What this portfolio project is

The portfolio project is Chloe LaForge's student-taught UVA course:

**CS 1501 --- Building Software with AI Systems**

The portfolio page is not merely presenting a class. It is presenting
the class itself as a designed system and as evidence of Chloe's ability
to: - teach technical concepts through interactive systems rather than
static explanations; - translate abstract software architecture into
interfaces that non-programmers can manipulate; - build AI-enabled
applications with deliberate constraints and human control; - connect
frontend, backend, APIs, databases, prompting, and AI behavior; - design
curriculum, software, and learning experiences together; - make
invisible system behavior visible; - teach students to understand what
AI can and cannot do rather than treating AI as a black box; - emphasize
authorship, oversight, scoping, and intentional delegation when building
with AI.

The portfolio should make it clear that Chloe did not simply teach
students to "use AI." She designed a course around understanding
systems, deciding what should remain human-controlled, and using AI
deliberately inside a larger software architecture.

Heading: **Same building blocks, different decisions**

Bullets: - Students choose which returned information actually reaches

## 19. Exercise: Control the decisions

Left media: **The specificity ladder**

It compares multiple versions of the same request with increasing
specificity.

Below it: **Control the decisions**

Bullets: - Three versions of the same request expose how much
decision-making the student is delegating. - The visual meter makes
specificity measurable instead of abstract. - Students focus on
authorship and control, not simply writing a longer prompt.

Conceptual point: Prompt quality is framed as allocation of decision

------------------------------------------------------------------------

## 20. Exercise: Scope the problem first

Right media: **Start with the actual problem**

The visual separates roles among: - HUMAN - DETERMINISTIC CODE - AI

Below it: **Scope the problem first**

Bullets: - The system separates human decisions, deterministic code, and
useful AI work. - Students visually identify where AI adds value before
deciding how to prompt it. - The exercise reframes AI integration as a
system-design choice rather than an automatic starting point.

Conceptual point: Students are taught not to begin every problem with
"how do I use AI?" They first define the actual problem, determine which
parts should be human-controlled, which are better handled
deterministically, and only then identify where AI is useful.

# 21. What the CS 1501 page is communicating overall

Across all sections, several ideas repeat intentionally.

### Make invisible systems visible

Frontend/backend requests, API composition, AI instructions, persistent
data, and model behavior are converted into interfaces students can see
and manipulate.

### Interaction over passive explanation

The course-content website is deliberately interactive. Students click,
toggle, choose, trace, assemble, and compare rather than only reading
definitions.

### Systems thinking before tool use

Students are taught to identify: - the actual problem; - system
boundaries; - human decisions; - deterministic behavior; - AI
behavior; - data flow; - interfaces; - external capabilities; -
constraints.

### Human authorship and control

The course repeatedly asks what the human should decide and what can be
delegated. AI is presented as a component within a designed system, not
as an autonomous replacement for the builder.

### Constraints are instructional

The five-message AI Friend budget is a deliberate example. Constraints
make tradeoffs and decision-making visible.

### Context matters

The AI Friend configuration becomes model instructions. Pre-class survey
responses become classroom context. System components receive and pass
information. The course repeatedly shows that output depends on the
context and structure surrounding a model call.

### Build to understand

The teaching philosophy is experiential: concepts become understandable
by interacting with a system that embodies them.

# 22. Relationship to the rest of Chloe's portfolio

The CS 1501 case study should feel related to AI Notebook without
collapsing into the same project.

**AI Notebook** demonstrates a product architecture for keeping AI
attached to visible, inspectable, user-controlled structure.

**CS 1501** demonstrates Chloe's ability to teach the broader reasoning
behind building software with AI: system architecture, APIs, data,
frontend/backend relationships, context, prompting, human control, and
intentional delegation.

The conceptual bridge is: **understanding the system instead of blindly
accepting AI output.**

CS 1501 adds an important dimension to the portfolio because it shows
that Chloe can not only build these ideas into software, but also turn
them into understandable interactive learning experiences for other
people.
